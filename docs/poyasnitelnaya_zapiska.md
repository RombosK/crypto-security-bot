# Пояснительная записка к учебному проекту

## «Криптобезопасный помощник» — Telegram-бот для защиты от мошенничества и генерации надёжных паролей

---

## 1. Введение

### 1.1. Актуальность темы

В современном цифровом мире человек ежедневно сталкивается с двумя ключевыми угрозами личной информационной безопасности:

1. **Слабые пароли.** По статистике, более 80% взломов аккаунтов происходят из-за ненадёжных паролей [4, 20]. Многие пользователи используют простые пароли типа «123456» или «password», которые взламываются мгновенно [41, 43].

2. **Социальная инженерия.** Мошенники звонят и пишут под видом сотрудников банков, полиции, родственников. По данным Банка России, в 2023–2024 годах россияне потеряли от телефонных мошенников десятки миллиардов рублей [25, 26].

Проект «Криптобезопасный помощник» — это Telegram-бот, объединяющий два модуля для защиты от этих угроз:
- генератор криптостойких паролей с оценкой их надёжности;
- анализатор сообщений на признаки мошенничества.

### 1.2. Цель проекта

Разработать учебный программный продукт на языке Python в виде Telegram-бота, который:
- генерирует надёжные пароли и математически оценивает их стойкость;
- анализирует текст сообщений на признаки мошенничества по взвешенной системе признаков;
- предоставляет пользователю рекомендации по защите.

### 1.3. Задачи

1. Изучить математические основы стойкости паролей (энтропия Шеннона, время перебора).
2. Реализовать алгоритм генерации паролей с использованием криптостойкого источника случайности.
3. Разработать систему взвешенных признаков мошенничества (15 признаков, 7 схем).
4. Создать Telegram-бота с интуитивным интерфейсом (команды и кнопки).
5. Протестировать все модули проекта.

## 2. Математические основы

### 2.1. Энтропия пароля

Стойкость пароля в криптографии измеряется в **битах энтропии** по формуле Клода Шеннона:

```
H = L × log₂(R)
```

где:
- **H** — энтропия (биты);
- **L** — длина пароля (количество символов);
- **R** — размер алфавита (количество возможных символов).

**Размер алфавита зависит от используемых классов символов:**

| Класс символов | Количество | Примеры |
|---|---|---|
| Строчные буквы | 26 | a, b, c... |
| Заглавные буквы | 26 | A, B, C... |
| Цифры | 10 | 0, 1, 2... |
| Специальные символы | 25 | !, @, #, $... |
| **Всего** | **87** | |

**Примеры расчёта энтропии:**

| Пароль | Длина | Алфавит | Энтропия | Время взлома |
|---|---|---|---|---|
| `123456` | 6 | 10 | 19.9 бит | мгновенно |
| `qwerty` | 6 | 26 | 28.2 бит | мгновенно |
| `MyP@ss1` | 7 | 87 | 44.2 бит | ~1 час |
| `MyStr0ng!Pass2024` | 16 | 87 | 102.8 бит | миллиарды лет |

### 2.2. Время взлома

Время полного перебора рассчитывается по формуле:

```
T = 2^(H−1) / V
```

где:
- **T** — время (секунды);
- **H** — энтропия (биты);
- **V** — скорость перебора (попыток в секунду).

Деление на 2 учитывает, что в среднем ответ находится на середине перебора.

В проекте используется оценка скорости перебора **10 млрд попыток/сек** — это современная оценка атаки по хешу на мощном оборудовании [17, 18, 19].

### 2.3. Шкала стойкости

| Энтропия | Оценка | Балл | Описание |
|---|---|---|---|
| < 28 бит | Очень слабый | 0–10 | 4-значный PIN |
| 28–36 бит | Слабый | 10–25 | 6 букв |
| 36–60 бит | Средний | 25–50 | 8 символов смешанных |
| 60–80 бит | Сильный | 50–75 | 12+ символов |
| ≥ 80 бит | Очень сильный | 75–100 | 16+ символов |

Эти пороги основаны на рекомендациях Национального института стандартов и технологий США (NIST SP 800-63B) [11, 14, 15].

## 3. Алгоритм антимошеннического анализа

### 3.1. Взвешенная система признаков

Анализ сообщения на мошенничество работает по принципу **взвешенной системы признаков**. Каждый признак имеет вес от 1 до 10 — чем выше вес, тем сильнее сигнал о мошенничестве.

**Всего определено 15 признаков. Примеры:**

| Признак | Вес | Описание |
|---|---|---|
| Требование перевести деньги | 8 | «переведите», «на счёт», «на карту» |
| Просьба назвать код из СМС | 9 | «код», «смс-код», «продиктуй код» |
| Ссылка на «безопасный счёт ЦБ» | 9 | «центральный банк», «безопасный счёт» |
| Создание срочности | 6 | «срочно», «немедленно», «быстрее» |
| Просьба раскрыть CVV/CVC | 10 | «cvv», «cvc», «пин-код» |
| Апелляция к семейным связям | 5 | «сын», «дочь», «мама» |

### 3.2. Расчёт скоринга

1. Текст приводится к нижнему регистру.
2. Для каждого из 15 признаков проверяется вхождение его ключевых слов в текст.
3. При нахождении ключевого слова соответствующий признак засчитывается (один раз).
4. Веса всех найденных признаков суммируются.
5. Итоговый скор: `score = min(100, total_weight × 10)`.

**Шкала уровней:**

| Скор | Уровень | Действие |
|---|---|---|
| 0–19 | Безопасно | Явных признаков нет |
| 20–49 | Подозрительно | Есть отдельные признаки |
| 50–74 | Опасно | Много признаков |
| 75–100 | Критично | Почти наверняка мошенничество |

### 3.3. База мошеннических схем

В проекте реализована база из **7 реальных схем** мошенничества, основанных на данных МВД и Банка России [24, 25, 26, 27]:

1. «Ваш родственник в беде»
2. «Безопасный счёт Центрального Банка»
3. «Вы выиграли приз»
4. «Гарантированный заработок на инвестициях»
5. «Вызывают в полицию»
6. «Назовите код из СМС»
7. «Лёгкая работа на дому»

Для каждой схемы хранится: название, ключевые слова, описание и инструкция «что делать». Если в тексте найдено 2 и более ключевых слов одной схемы, она засчитывается как совпавшая.

## 4. Технологии и архитектура

### 4.1. Стек технологий

| Компонент | Технология | Назначение |
|---|---|---|
| Язык программирования | Python 3.10+ | Основной язык |
| Telegram Bot API | aiogram 3.x | Взаимодействие с Telegram |
| Источник случайности | `random.SystemRandom` | Криптостойкий генератор |
| Хранение данных | JSON | Лог проверок |
| Конфигурация | `.env` + `python-dotenv` | Токен бота |

### 4.2. Модульная архитектура

Проект разделён на независимые модули:

```
src/
├── config.py            — конфигурация (токен, настройки)
├── password_engine.py   — генерация и оценка паролей
├── fraud_detector.py    — анализ мошенничества
└── main.py              — Telegram-бот (связывает модули)
```

**Принцип разделения ответственности:**
- `password_engine.py` не знает о Telegram — чистая логика паролей
- `fraud_detector.py` не знает о Telegram — чистая логика анализа
- `main.py` связывает логику с Telegram Bot API

Это позволяет:
- использовать модули в других проектах (веб, CLI, другие мессенджеры);
- тестировать логику отдельно от бота;
- расширять проект без переписывания.

### 4.3. Источник случайности

Для генерации паролей используется `random.SystemRandom()` — класс из стандартной библиотеки Python, который обращается к криптостойкому источнику случайности операционной системы (на Linux — `/dev/urandom`) [16, 21]. Это принципиально отличается от обычного `random.random()`, который использует псевдослучайный генератор и непригоден для паролей.

- Короткий текст без пробелов — бот проверяет как пароль

- Можно перешлите подозрительное сообщение боту

## 7. Ограничения и направления развития

### Ограничения текущей версии:
1. Анализ текста основан на ключевых словах, а не на семантике — хитрые мошенники могут перефразировать.
2. База схем статична — не обновляется автоматически.
3. Лог хранится в JSON-файле, а не в базе данных.
4. Нет админ-панели для управления базой схем.

### Возможные направления развития:
1. **Машинное обучение** — классификатор на основе датасета мошеннических сообщений.
2. **База данных** — SQLite/PostgreSQL вместо JSON.
3. **Многоязычность** — анализ сообщений на других языках.
4. **Веб-версия** — веб-интерфейс на основе модулей `password_engine` и `fraud_detector`.
5. **API** — REST API для интеграции в другие сервисы.
6. **Уведомления** — рассылка о новых схемах мошенничества.

## 8. Заключение

В результате работы был разработан Telegram-бот «Криптобезопасный помощник», объединяющий два модуля:

1. **Генератор паролей** — использует криптостойкий источник случайности, рассчитывает энтропию по формуле Шеннона [5] и оценивает время взлома перебором [17].

2. **Антимошеннический анализатор** — использует взвешенную систему из 15 признаков и базу из 7 реальных схем мошенничества для оценки подозрительности сообщений на основе аналитики ЦБ РФ и МВД [25, 27].

Проект имеет модульную архитектуру, что позволяет использовать каждый модуль независимо и расширять проект без переписывания. Все модули протестированы и работают корректно.

Проект демонстрирует практическое применение:
- математических понятий (энтропия, логарифмы, комбинаторика);
- алгоритмического мышления (взвешенный скоринг, поиск по ключевым словам);
- принципов информационной безопасности (криптостойкая случайность, оценка стойкости);
- работы с API (Telegram Bot API через aiogram [15, 16]).
